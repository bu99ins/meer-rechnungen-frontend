# Development Guide

## Environment setup

Local development uses the committed `.env.development`, which targets the docker-compose
backend:

```
VITE_API_URL=http://localhost:5000
```

The backend's CORS policy allows `http://localhost:5173`, so no Vite proxy is needed. For
deployed builds, `VITE_API_URL` is supplied at build time (the deployed backend's HTTPS URL)
instead, along with `VITE_API_GATE_KEY` (see [api-contract.md](api-contract.md)).

## Scripts

| Command | Purpose |
|---------|---------|
| `npm run dev` | Start Vite dev server (hot reload) |
| `npm run build` | TypeScript check (`tsc -b`) + Vite production build |
| `npm run lint` | ESLint check |
| `npm test` | Run unit tests with Node's built-in runner (`node --test`) |
| `npm run preview` | Preview production build locally |

## Build output

- **Directory**: `dist/`
- **Generated by**: Vite (from `index.html` + bundle)
- Served as a static SPA (all routes → `index.html`); no server-side rendering

## TypeScript configuration

- **Target**: ES2020 (`tsconfig.app.json`)
- **Strict mode**: enabled
- **No unused locals/params**: enforced — unused symbols fail the build
- **Build info cache**: `node_modules/.tmp/`

## Development patterns

### Adding a new page/entity

1. Create folder in `src/pages/<newentity>/`
2. Add List, Details, Form components
3. Add service file in `src/services/<newentity>.ts`
4. Add Zustand store in `src/store/<newentity>Store.ts`
5. Add types in `src/types/<newentity>.ts`
6. Add routes in `App.tsx` (List, Create, Details, Edit)

### Adding a new API endpoint

1. Create/update the service function in `src/services/`
2. Add it to the corresponding Zustand store as an action
3. Call the store action from the page component
4. Handle loading/error states in the component

### Form component pattern

- Generic `<Form />` component takes config + handlers
- Pages import and use it with entity-specific fields
- Submit calls the store action → service → axios

## Deployment

Deployment is a manually triggered GitHub Actions workflow
([.github/workflows/deploy-frontend.yml](../.github/workflows/deploy-frontend.yml)) that builds
with the production env vars and publishes `dist/` + `functions/` to Cloudflare Pages. See
[CLAUDE.md](../CLAUDE.md#deployment) for the gating rules and required repo variables/secrets.
